# 0016. 선택 판정은 원문을 제외한 제한된 감사 기록으로 먼저 영속화한다

- 상태: Accepted
- 날짜: 2026-08-27
- 범위: selection, daemon composition

## 맥락

Selection은 Card별 판정뿐 아니라 최소 충분 집합까지 계산하지만, 기존 상세 감사 값은 한 요청의
`SelectionPlan` 안에서만 존재했다. 프로세스가 끝나면 어떤 Card가 어떤 점수와 정책으로 남았고
어떤 Card가 집합 계획에서 제외됐는지 확인할 수 없었다. 반대로 질의 원문, 정규화 토큰, 일치한
Card 문자열을 그대로 운영 로그에 남기면 외부 지식을 찾으려던 사용자의 입력과 민감한 단어가
새로운 장기 저장소로 복제된다.

## 결정

Selection은 완성된 계획을 `SelectionAuditRecord`로 투영하고 daemon은 관리 문서 검색을 실행하기
전에 이를 `SelectionAuditStore`에 추가한다. 추가가 실패하거나 제한 시간을 넘으면 요청은 닫힌
실패로 끝나며 어떤 검색 대상도 실행하지 않는다. CLI 제품 조립은 상태 식별자가 고정된 별도 SQLite
저장소를 사용하되, 동기식 `node:sqlite` 연결은 수명이 긴 전용 Worker가 소유한다. 따라서 요청의
제한 시간은 실제 비동기 경계를 중단할 수 있고 SQLite가 event loop를 붙잡아 타이머를 무력화하지
않는다. 내장 조립과 집중 시험은 같은 포트의 제한된 인메모리 어댑터를 사용한다.

기록에는 불투명 감사 식별자와 시각, 질의 UTF-8 바이트 수, 정책 버전과 임계값, 전체 후보·정책
제외·판정 개수와 후보 집합 다이제스트를 둔다. 상세 근거는 계획에 유지된 Card와 높은 판정부터
최대 128개만 남기며 Card·버전 식별자, 점수, 신호 종류별 기여도, 독립 판정 규칙, 정책 제외,
최소 집합 비용·결정·대체 관계를 담는다. 질의
원문, 정규화된 관점·토큰, 일치 문자열, 사람이 읽는 판정 메시지, 질의에서 파생된 관점 식별자와
그 전체를 해시한 계획 다이제스트는 저장하지 않는다. 관점 연결이 필요하면 한 기록 안에서만 의미가
있는 `facet_1` 형식의 순번을 쓴다. 저장된 전체 투영에는 무결성 다이제스트를 붙인다.

보존 정책은 현재 시각 기준 30일, 10,000건, 전체 256 MiB, 기록당 2 MiB 중 먼저 닿는 한도다. 새
기록과 정리는 한 트랜잭션에서 수행한다. DB는 SQLite application ID·user version, 정확한 스키마,
상태 네임스페이스와 보안 영역을 함께 확인하고 DB·WAL·SHM을 소유자 전용 파일 모드로 만든다. 비어
있지 않은 미식별 DB, 다른 상태 식별자, WAL만 남은 불완전 스냅샷, 손상된 바이트·다이제스트는 자동
수용하지 않는다.

조회는 로컬 `contextctl audit list/show`만 제공한다. `list`는 고정 크기·자체 다이제스트가 있는
요약만 읽고 `show`만 상세 한 건을 읽는다. 질의와 기록은 응답 계약을 늘리지 않고 보호된 daemon
stderr의 감사 식별자로 연결한다. MCP와 HTTP에는 제어·감사 표면을 추가하지 않는다. `status`와
`doctor`는 저장소의 호환성을 읽기 전용으로 검사한다. 단기 운영 추적 자료이므로 제품 상태 백업에는
포함하지 않는다.

## 기각한 대안

- **질의 원문과 일치 문자열까지 저장한다**: 분석은 쉽지만 원래 외부 지식과 별개인 민감 로그 저장소를 만든다.
- **계획 다이제스트만 저장한다**: 무결성은 확인해도 어떤 Card와 정책이 결정을 만들었는지 설명할 수 없다.
- **프로세스 메모리에만 둔다**: 장애·재시작 뒤 운영자가 판정을 추적할 수 없다.
- **검색 뒤 비동기로 기록한다**: 기록 실패를 성공 응답과 분리해 감사할 수 없는 원본 접근을 허용한다.
- **MCP·HTTP로 조회한다**: 에이전트용 데이터 표면에 운영자 제어 자료를 섞고 원격 노출 범위를 넓힌다.
- **무기한 보존하거나 제품 백업에 포함한다**: 최소 정보 투영이어도 Card 관계와 사용 패턴이 불필요하게 누적된다.

## 대가

- 질의마다 SQLite 트랜잭션 하나와 Worker 메시지 왕복이 검색 전에 추가된다. Worker는 요청마다
  생성하지 않고 CLI runtime 수명 동안 재사용한다. 단일 daemon의 제한된 로컬 저장소를 전제로 하며
  지연·동시 부하 Gate에서 계속 측정한다.
- 감사 저장소 장애는 검색 가용성을 막는다. 판정은 기록 가능한 경우에만 원본 접근 권한으로 사용할
  수 있다는 의도적인 닫힌 실패다.
- 원문을 저장하지 않으므로 특정 표현이 왜 한 신호와 일치했는지는 이 기록만으로 재현할 수 없다.
  저장된 정책 버전과 Card 버전을 같은 고정 평가 자료에서 다시 실행해 조사한다.
