# 0003. MCP에 control plane을 노출하지 않는다

- 상태: Accepted
- 날짜: 2026-07-31
- 범위: selection

## 맥락

MCP 서버는 AI 에이전트용 주요 인터페이스다. 조회 도구를 노출하는 김에 승인·거부·
롤백·동기화·수정까지 같은 표면에 얹으면 에이전트가 운영까지 자동화할 수 있다.
구현 비용도 거의 들지 않는다. 그래서 안 하는 쪽이 의도적 결정임을 남긴다.

## 결정

MCP에는 **조회 계열만** 노출한다. `approve` `reject` `rollback` `sync` `edit`에
해당하는 도구를 두지 않는다. control plane은 운영자용 CLI와 HTTP로만 접근한다.

## 기각한 대안

- **control plane 전체를 MCP로 노출**: 이 제품의 가치는 "AI가 소비하는 컨텍스트를
  **사람이** 거버넌스한다"다. AI가 자기 컨텍스트를 스스로 승인할 수 있으면
  거버넌스가 붕괴한다 — 승인이라는 절차만 남고 통제는 사라진다.
- **조회 + 승인만 노출하고 롤백·수정은 제외**: 경계가 판단에 의존한다. 어떤 도구가
  "위험한지"를 매번 판단해야 하고 새 도구가 추가될 때마다 다시 논쟁이 된다.
  계열 단위로 닫는 편이 검증 가능하다.
- **MCP에 운영자 인증을 얹어 노출**: 에이전트가 운영자 자격증명을 갖게 되면
  사람의 승인과 AI의 승인을 사후에 구분할 수 없다. 감사 이력의 의미가 사라진다.

## 대가

- 운영자는 MCP만으로 작업을 완결할 수 없다. 승인·롤백은 CLI 또는 HTTP로 가야 한다.
- 도구 목록이 조용히 늘어나는 것을 막을 장치가 필요하다 →
  `tools/list`가 정확히 N개이고 control plane 이름이 부재함을 **회귀 테스트로 못 박는다.**
  테스트 없이는 이 결정이 다음 커밋에 무너진다.
