# 0011. `selection-eval-v1`으로 어휘·혼합 점수를 교정하고 정책 버전을 v2로 올린다

- 상태: Accepted
- 날짜: 2026-08-24
- 범위: selection

## 맥락

ADR 0010은 `selection-lexical-v1`의 부분문자열 점수와 0.9 직접 일치 하한이 같은 문서의 Card를 함께 승인하는 결함을 기록하고, 고정 평가 자료 없이 임계값이나 공식을 바꾸지 않기로 했다. 최종 설계는 50개 질의를 보정 30개와 홀드아웃 20개로 고정한 `selection-eval-v1`을 요구한다.

고정 평가 자료를 만든 뒤 v1을 측정하자 흔한 한 단어와 부분문자열만으로 관련 없는 Card가 승인되고, 두 약한 신호에 0.1 합의 보너스를 더하는 혼합 공식도 금지 대상을 승인했다. 이 결함은 임계값만 옮겨서는 관련 Card의 재현율을 함께 잃으므로 점수 의미 자체를 새 버전으로 교정해야 했다.

## 결정

어휘 정책은 `selection-lexical-v2`, 혼합 정책은 `selection-hybrid-v2`로 올린다.

어휘 v2는 설명, 대표 질문, 별칭, 키워드와 공개 Scope 좌표를 토큰화한다. 필드 가중 BM25와 문자 2·3-gram Dice를 `0.75:0.25`로 결합하되 간접 신호만으로는 거부 영역 상한 `0.34`를 넘지 못한다. 키워드·별칭·Scope의 직접 신호는 카탈로그 내 빈도로 특이성을 계산한다. 흔하고 문맥이 약한 선언은 보류 영역 상한 `0.84`를 넘지 못하며, 질의가 문서·SQL·HTTP 종류를 명시했는데 Card 종류가 다르면 같은 제한을 적용한다. 한국어는 제한된 조사 제거와 두 글자 이상 선언 토큰의 접두 일치만 허용하며 임의 부분문자열은 사용하지 않는다.

Card가 128개 이상인 카탈로그에서는 결합 전 간접 점수 `0.05` 미만을 증거 없음으로 처리한다. 작은 카탈로그의 약한 어휘 단서가 top-K 회수에 기여하는 동작은 유지하되, 큰 카탈로그에서 질문 한 단어의 우연한 2·3-gram 겹침이 수천 장의 양수 점수와 감사 신호 객체를 만드는 것을 막는다. 이 하한은 승인·보류 경계를 옮기지 않으며, 대규모 카탈로그에서만 거부 영역 아래의 노이즈를 0으로 정규화한다.

혼합 v2는 다음 규칙을 사용한다.

1. 코사인 `0.85` 이하는 단독 절대 근거로 쓰지 않는다.
2. 의미 검색의 1위가 코사인 `0.80` 이상이고 2위와 차이가 `0.03` 이상이면 승인 경계 점수 `0.85`를 보장한다.
3. 1위가 아닌 의미 후보는 `0.34`를 넘지 못한다.
4. 어휘와 의미 점수는 `max`로 결합한다. 약한 두 신호를 더하는 합의 보너스는 0이다.
5. 적격 Card를 정책으로 먼저 제외한 뒤 어휘 top 32와 의미 top 32의 합집합을 결정적으로 순위화한다.

평가 자료와 분할 다이제스트를 코드에 고정하고, Granite fp32 실제 제공자와 실제 후보 Index를 사용한 조건부 통합 검사를 필수 Granite 검사에 연결한다. 홀드아웃은 보정에 다시 사용하지 않는다.

## 검증 결과

고정 홀드아웃 20개에서 어휘 v2는 required recall@5 `1.0`, 승인된 필수 Card 재현율 `0.9048`, 다중 정답 전부 승인율 `0.8333`, 질의 판정 macro F1 `0.9515`, 모호 질의 승인·보류 macro F1 `0.9`, 무관 질의 오승인율 `0`, 금지 Card 승인 `0`을 기록했다.

실제 Granite 혼합 경로의 홀드아웃 결과는 required recall@5 `1.0`, 승인된 필수 Card 재현율 `0.9524`, 다중 정답 전부 승인율 `0.8333`, 질의 판정 macro F1 `1.0`, 모호 질의 승인·보류 macro F1 `1.0`, 무관 질의 오승인율 `0`, 금지 Card 승인 `0`, p95 `8.30ms`, 질의당 임베딩 최대 1회다. 같은 자료의 어휘 경로보다 모호 질의 macro F1을 `0.10` 개선해 절대 품질·비퇴행·개선 기준을 모두 통과했다. 기계 판독 결과는 CI 산출물로 보존한다.

10,000장 고정 규모 자료에서는 질의와 무관한 9,999장이 `0.0139~0.0143`의 우연한 간접 점수와 10,000개의 신호 객체를 만들던 상태가 모두 0점·공유 빈 신호로 바뀌었다. 같은 카탈로그 세대의 0점 후보 레코드도 불변 값으로 재사용한다. 같은 50회 어휘 질의의 로컬 RSS 증가분은 약 `140MiB`에서 `28MiB`로 줄었고, 실제 Granite 규모 검사의 p95는 `46.65ms`, 최고 RSS는 `937.75MiB`였다. 운영 `SelectionPlan` 경로는 Hybrid 결합으로 점수가 실제로 바뀐 후보만 새 기본 후보 객체로 만들고, 상세 Hybrid 진단 API는 기존 신호별 반환을 유지한다.

## 기각한 대안

- **v1 이름을 유지하고 공식만 바꾼다**: 같은 정책 토큰의 의미를 바꾸므로 금지한다.
- **임계값만 높인다**: 흔한 직접 일치의 0.9 하한과 관련 Card가 겹쳐 재현율을 함께 잃는다.
- **어휘 점수를 의미 top-K의 재순위에만 쓴다**: 어휘에 보이지 않는 의미 후보를 찾을 수 없어 혼합 검색이 아니다.
- **두 신호를 더하거나 합의 보너스를 유지한다**: 보정 자료에서 금지 Card 승인을 만들었다.
- **의미 유사도 하나의 절대 임계값만 쓴다**: 관련·금지 분포가 겹친다. 1위와 2위 차이를 함께 보지 않으면 안전성과 재현율을 동시에 만족하지 못했다.

## 대가

- 정책 리터럴과 스키마 불변식, daemon 렌더링·회귀 기준을 함께 올려야 한다.
- BM25 통계와 모든 Card의 어휘 점수를 요청마다 계산하므로 승인 카탈로그 최대 규모의 지연 시간은 별도 `selection-scale-v1`로 검증하고 최적화해야 한다.
- 현재 보정은 고정 Granite fp32 프로필과 평가 자료에 종속된다. 프로필, 입력 변환이나 임계값을 바꾸면 새 버전과 같은 평가가 필요하다.
