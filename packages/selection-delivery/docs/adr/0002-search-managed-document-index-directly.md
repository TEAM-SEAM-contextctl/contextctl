# 0002. 관리 문서 인덱스는 Selection이 직접 검색한다

- 상태: Superseded by 0008
- 날짜: 2026-07-30
- 범위: selection

## 맥락

ADR 0001은 소비자의 원본을 실행하지 않는다고 정했다. 그러면 우리가 직접 게시한 문서
인덱스도 같은 원칙으로 읽지 않아야 하는가.

읽지 않는 쪽을 택하면 소비자는 Vector DB 접속 정보와 임베딩 모델을 직접 갖춰야 한다.
MCP로 연결된 AI 에이전트에는 둘 다 없다.

## 결정

선택된 Retrieval Scope 안에서 Chunk를 검색하고 Managed Document Evidence로 조립해
반환한다. 검색 대상은 **우리가 게시한 인덱스로 한정한다.**

검색 port는 Selection이 소유하고, Vector DB adapter 연결은 daemon이 조립한다.

## 기각한 대안

- **문서도 좌표만 주고 레퍼런스 클라이언트를 별도 제공**: README에 "쓰려면 이것도 구현하세요"가
  붙는 순간 채택 장벽이 된다. MCP 소비자에게 벡터 검색을 요구하면 MCP 인터페이스가 반쪽이 된다.
- **같은 논리로 외부 DB에도 질의**: ADR 0001과 충돌한다. 우리가 게시한 인덱스는 권한, 커넥션
  풀, 감사가 우리 것이지만 외부 원본은 그렇지 않다. 경계는 "실행하느냐"가 아니라
  "무엇에 대한 책임을 우리가 갖고 있느냐"에 있다.

## 대가

- Selection이 검색 실행 경로를 갖는다. token budget, 중복 제거, 결과 절단이 이 도메인
  책임으로 들어온다.
- ADR 0001과 경계가 미세해 보인다. "원본은 실행하지 않지만 인덱스는 읽는다"는 설명이
  매번 필요하다. 그 설명 비용을 줄이려고 이 기록을 남긴다.

## 참고
